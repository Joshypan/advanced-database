SQL in Python

Python supplies the values and decides what happens next.

Structured Query Language (SQL) remains the language of the database operations. Python supplies program control and in-memory values. Source: chapter-02-sql-in-python.md and ../../topic-02-sql-in-python/db-example.py. Code blocks use readable line breaks; smaller variations are identified in the notes.

Running the Example

python3 db-example.py --db practice.db

The script rebuilds the pet table on every run.

Run from topic-02-sql-in-python. Separate practice database. Without --db, pets.db is the default in the working directory. Repeatable demonstration, not startup behavior for an application preserving user records.

Choosing a Database

import argparse
import sqlite3

ap = argparse.ArgumentParser()
ap.add_argument("--db", default="pets.db")
args = ap.parse_args()
connection = sqlite3.connect(args.db)

args.db supplies the filename.

argparse reads command-line arguments; sqlite3 opens the connection. The source also imports pprint for readable output. The connection is a Python object; the file can survive the process. Relative filenames depend on the current working directory. References: https://docs.python.org/3/library/argparse.html and https://docs.python.org/3/library/sqlite3.html.

Python Calls, SQL Statements

connection.execute("drop table if exists pet")
connection.commit()

Python calls the method. SQLite interprets the string.

IF EXISTS permits a fresh database with no pet table. An existing pet table and its rows are removed. The next CREATE TABLE restores the familiar id, name, kind, age, food definition. Triple-quoted Python strings hold multiline SQL. Syntactically valid Python can contain invalid SQL.

Inspecting the Tables

cursor = connection.execute("""
    SELECT name FROM sqlite_master
    WHERE type = 'table' ORDER BY name
""")
list_of_tables = [item[0] for item in cursor.fetchall()]
['pet', 'sqlite_sequence']
SQL query replaces the shell's .tables command. sqlite_master names the schema table. Each one-column result is still a tuple; item[0] extracts the name. The result shown is after creating pet. sqlite_sequence may remain from an earlier run even after dropping pet, so the initial list is not always empty.

SQL and Values Travel Separately

connection.execute(
    "INSERT INTO pet (name, kind, age, food) "
    "VALUES (?, ?, ?, ?)",
    ("Dorothy", "dog", 11, "peanut butter"),
)

Four placeholders. Four values, in the same order.

Adjacent Python string literals join into one SQL string. Values can come from variables. Parameter binding handles an apostrophe in O'Malley without constructing SQL quotes. Placeholders represent values, not table names. The driver binds the values separately from SQL syntax. Source example with line breaks adjusted.

Committing Changes

connection.execute(
    "INSERT INTO pet (name, kind, age, food) "
    "VALUES (?, ?, ?, ?)",
    ("Whiskers", "hamster", 1, "hamster chow"),
)
connection.commit()

Dorothy and Whiskers precede this commit.

With the script's connection settings, both inserts belong to the pending transaction. Commit applies to that transaction, not only the last statement. The same connection can read its uncommitted changes. Visibility there does not prove another process will find the changes later. Other transaction settings behave differently; transaction detail belongs later in the course.

Fetching One Row

cursor = connection.execute("SELECT * FROM pet")
row = cursor.fetchone()
pprint(row)
(1, 'Dorothy', 'dog', 11, 'peanut butter')

A stored record becomes a Python tuple.

Observed result from the tested script. Column order follows SELECT *. Row order is unspecified without ORDER BY. fetchone returns None after no rows remain. pprint displays the Python value; it does not query the database.

Fetching the Remaining Rows

cursor = connection.execute(
    "SELECT name FROM pet ORDER BY id"
)
first = cursor.fetchone()
rest = cursor.fetchall()
first: ('Dorothy',)
rest:  [('Whiskers',)]
Small variation illustrating cursor consumption after the initial two inserts. fetchall retrieves remaining rows. The original script re-executes SELECT * before fetchall, so its list includes Dorothy again. Fetching is not the same as running the query again.

The One-Element Tuple

cursor = connection.execute(
    "SELECT sql FROM sqlite_master "
    "WHERE type='table' AND name=?",
    ("pet",),
)
row = cursor.fetchone()
pprint(row[0] if row else "")

("pet",) is a tuple. ("pet") is a string.

The comma creates the tuple. One placeholder needs one parameter value. A one-column result is also a tuple; row[0] extracts its string. The conditional handles None when the requested table is absent.

An Error Does Not Fix Itself

try with a wrong name
Caught sqlite error: no such table: petz
Caught sqlite error: no such table: petz

Catching the exception lets the program continue.

Repeating the same misspelling fails again.

The source loops twice around an insert into petz, catching sqlite3.Error as e. It then uses the correct pet table, commits Sandy, and breaks after success. The first loop adds no records. break controls the Python loop. Exception handling and deciding what to roll back are separate responsibilities.

Deleting Stash

connection.execute(
    "DELETE FROM pet WHERE name=?",
    ("Stash",),
)
connection.commit()

The condition can match more than one record.

Before this deletion, the script adds Maxwell and Stash and commits them. name is not unique in the schema. A missing name can produce zero matching rows without an exception. A completion message reports execution, not necessarily a changed record.

Updating Dorothy

connection.execute(
    "UPDATE pet SET age=?, food=? WHERE name=?",
    (12, "pretzels", "Dorothy"),
)
connection.commit()

SET supplies changes. WHERE selects records.

Fully parameterized variation from the chapter. The source embeds age 12 and pretzels in SQL and binds only the name. Dorothy retains id 1 and kind dog. No matching rows need not raise an error. Reassigning a Python variable alone does not update this record.

The Final Stored State

id name kind age food
1 Dorothy dog 12 pretzels
2 Whiskers hamster 1 hamster chow
3 Sandy cat 9 tuna
4 Maxwell cat 11 tuna

A new process can retrieve these records.

Verified by running the actual script against a temporary database, then opening a separate connection. Stash deleted; petz attempts added nothing. Whiskers is 1 here, unlike 11 in the introductory terminal transcript. Shell verification: sqlite3 practice.db -header -column "SELECT * FROM pet ORDER BY id;".

Finishing with the Connection

connection = sqlite3.connect("practice.db")
try:
    cursor = connection.execute(
        "SELECT name FROM pet ORDER BY name"
    )
    pprint(cursor.fetchall())
finally:
    connection.close()

Closing is not a substitute for committing.

Additional cleanup pattern from the chapter, not present in the original script. Explicit close releases the connection when its work is finished. Python values and stored records have separate lifetimes. The next topic connects operations to web requests; database abstraction later collects the operations into functions.
